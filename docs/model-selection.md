## 결론

| 역할 | 모델 | 이유 한 줄 |
|---|---|---|
| **기본** | `gemini-3.8-flash` | 프롬프트를 세 번 바꾸는 동안 잘못된 답변 0건·상태 정확도 120/126을 한 번도 벗어나지 않은 유일한 모델 |
| **대체** | `gpt-5.4-mini` | 다른 제공사(OpenAI), 최종 프롬프트에서 잘못된 답변 0건, 이전 운영 모델이라 실사용 이력 있음 |

- 비용 최적화 후보로 `gemini-3.5-flash-lite`를 대기 목록에 둠 (최종 지표는 같고 비용 절반, 대신 프롬프트 변화에 민감)
- 트래픽이 커지거나 2027-01-01 Gemini 3.8 가격 인상 시점에 다시 평가

## 1. 왜 비교했나

- **모델 하나에 묶여 있었음**
  - 1단계는 `gpt-5.4-mini` 하나로 설계·평가. 다른 모델이 더 낫거나 싼지 판단할 근거가 없었음
  - 제공사 하나가 장애·가격 인상·모델 종료를 겪으면 서비스 전체가 같이 멈춤
- **모델은 계속 나오고 바뀜**
  - 조사 시점에 OpenAI만 해도 이 키로 쓸 수 있는 저가 모델이 `gpt-4.1` · `gpt-5` · `gpt-5.4` · `gpt-6-luna` 세대에 걸쳐 있음
  - Gemini 2.5 세대는 신규 사용자 접근이 막히는 중 (실제로 `gemini-2.5-flash-lite`는 404)
  - "새 모델이 나오면 한 줄 추가하고 같은 평가를 돌리는" 구조가 필요
- **이 서비스에서 중요한 건 일반 성능이 아님**
  - 공개 벤치마크 점수보다 "근거가 없으면 모른다고 말하는가"가 핵심
  - 같은 평가셋·같은 지표 우선순위(잘못된 답변률 → 상태 정확도 → 비용)로 직접 재야 함

## 2. 실험 설계

### 고정한 것

- **평가셋**: 42문항 그대로 (직접 13 · 구어체 12 · 여러 문서 7 · 준비 중 3 · 문서에 없음 7)
- **검색**: 임베딩 모델·검색 하한(0.15)·상위 5개 모두 고정
  - 모든 모델이 같은 근거 조각을 받음 → 차이는 생성 모델의 판단에서만 생김
  - 그래서 검색 적중률은 모든 모델에서 97.1% (102/105)로 같음
- **추론 설정**: 제공사마다 이름이 달라서 "낮음"으로 맞춤
  - OpenAI 추론 모델: `reasoning.effort: low`
  - Gemini 3.x: `thinkingLevel: LOW`
  - Gemini 2.5: `thinkingBudget: 1024` (thinkingLevel 없음. 설정 안 하면 동적 추론이라 짧은 질문도 27초)
  - `gpt-4.1` 계열: 추론 설정 없음 (보내면 400)
- **코드 가드**: 인용 없는 답 → 근거 없음, 준비 중 문서 인용 → 준비 중 정책. 모든 모델에 똑같이 적용

### 바꾼 것

- 생성 모델만. `npm run eval -- --model <id> --runs 3`

### 지표

- **잘못된 답변률** (최우선): 답하면 안 되는 10문항 × 3회 = 30건 중 답한 건수
- **최악 회차**: 3회 중 잘못된 답변이 가장 많았던 회차의 건수
- **상태 정확도**: 42 × 3 = 126건 중 기대 상태와 같은 건수
- **과잉 거절률**: 답해야 하는 32 × 3 = 96건 중 거절한 건수
- **흔들린 문항**: 회차마다 판단이 달라진 문항 수
- **질문 1,000건 비용**: 공식 유료 단가로 환산 (2026-09-27 확인)
  - 검색 결과가 없어 모델을 안 부른 질문도 분모에 포함 → 실제 운영 단가
  - Gemini는 무료 티어로 돌렸지만 비교는 유료 단가로. 캐시 할인은 빼고 보수적으로 계산
- **응답 시간 p50 / p95**: 판단 호출 1회 기준, 한국 가정용 회선에서 측정 (네트워크 포함)

### 3회씩 돌린 이유

- 첫 평가에서 **같은 설정이 README 수치와 다르게 나옴**
  - `gpt-5.4-mini`: 이전 기록 40/42·잘못된 답변 0 → 재평가 38/42·잘못된 답변 1
  - 다시 돌리니 40/42·0으로 돌아옴
- 한 번 실행한 결과로는 모델 차이와 실행마다의 흔들림을 구분할 수 없음
- 그래서 모델마다 3회 실행, 합산 비율·최악 회차·흔들린 문항을 함께 기록

## 5. 실험 2 — 평가 도구 자체의 결함

- `gemini-2.5-flash-lite` 평가에서 126건 호출이 **전부 404로 실패**
- 그런데 결과표에는 **잘못된 답변률 0%**
  - 실패한 호출을 "답하지 않음(unanswerable)"으로 채점했기 때문
  - 비교표는 잘못된 답변률로 정렬 → **아무것도 못 한 모델이 1위에 오를 뻔함**
- 고친 것
  - 호출 실패율이 20%를 넘으면 그 평가는 무효: 남은 회차를 멈추고 결과를 저장하지 않음
  - 비교표에서 호출 실패가 있는 모델은 순위 맨 뒤, ⚠ 표시
- 교훈: 지표가 좋아 보이면 먼저 "측정이 제대로 됐는가"를 확인. 실패를 안전한 쪽으로 채점하면 장애가 성과로 보임

## 6. 실험 3 — q41 프롬프트 수정 (3차까지)

- 방식: 규칙 하나를 바꿀 때마다 대표 모델 6개를 3회씩 다시 평가하고 전후 비교
  - 대표 모델: q41을 3회 모두 틀린 `gpt-5.4-nano`·`gemini-3.5-flash-lite`, 운영 모델 `gpt-5.4-mini`, 1위권 `gpt-5-mini`·`gemini-3.8-flash`(부작용 감시), 최저가 `gpt-6-luna`
- 멈추는 조건을 미리 정함: 3차까지. 42문항에 맞춰 계속 고치면 평가셋에만 맞는 프롬프트가 됨

### 1차 — "언제" 질문에 시점이 없으면 거절

- 규칙: 질문이 시점·계획을 묻는데 근거에 그 시점이 없으면, 현재 상태가 있어도 unanswerable
- 결과 (OpenAI 4개만 측정): 잘못된 답변은 줄었지만 **과잉 거절 증가**
  - `gpt-5.4-mini` 과잉 거절 6 → 9, `gpt-6-luna` 9 → 11
  - 새로 틀린 문항: q19 "다음 시즌 언제 나와요?", q33 "광고형 요금제 언제 나와요?"
- 원인: q19·q33도 "언제"를 묻지만 문서에 **응대 기준**("공지된 일정만 안내", 준비 중 정책)이 있어 답할 수 있는 질문. 규칙이 너무 넓었음
- Gemini 2개는 실행 스크립트 실수(PATH 누락)로 측정되지 않음 → 2차부터 6개 모두 측정

### 2차 — 응대 기준이 있으면 예외

- 규칙 추가: 근거에 그런 질문을 어떻게 안내할지(응대 기준)가 있으면 그 기준을 답으로 봄
- 결과: 대부분 개선, 하지만 `gpt-5-mini`가 **새로 나빠짐** (잘못된 답변 0 → 2)
  - q40 "스포츠 생중계도 해요?"에 **콘텐츠 업로드 일정의 응대 기준**을 끌어다 answered
  - 답변 본문에 "생중계 여부는 근거에 명시되어 있지 않습니다"라고 쓰고도 상태는 answered (본문과 상태가 모순)

### 3차 — 같은 대상의 기준만, 모순 금지

- 규칙 수정
  - "질문한 바로 그 대상(같은 콘텐츠·기능·요금제)에 대한 응대 기준"만 인정, 다른 대상의 기준을 끌어다 쓰지 않음
  - text에 "근거에 없다", "명시되어 있지 않다"고 쓰는 답은 answered가 아님

- 기준 · 2차 · 3차 세 번 모두 잘못된 답변 0 · 정확도 120 · 과잉 거절 6. 흔들린 문항 0
- 비교 대상
  - `gemini-3.5-flash-lite`: 기준 프롬프트에서 q41을 **3회 모두** 틀림. 규칙을 추가한 뒤에야 같아짐
  - `gpt-5.4-mini`: 기준 q41 1회, 1차 과잉 거절 9, 2차 7로 매번 조금씩 움직임
  - `gpt-5-mini`: 기준에선 1위였지만 2차부터 q40으로 무너짐
- 프롬프트는 앞으로도 계속 고칠 것 → 규칙 문구에 덜 민감한 모델이 운영 위험이 작음

### 비용: 이 규모에서는 차이가 의미 없음

- 공개 데모 하루 상한 300회 기준 최대 비용
  - gemini-3.8-flash: 약 $0.33/일 (월 $10 이하)
  - gemini-3.5-flash-lite: 약 $0.15/일
  - gpt-5.4-mini: 약 $0.41/일
- 하루 $0.2 차이로 안정성을 포기할 이유가 없음
- 이전 운영 모델(`gpt-5.4-mini`)보다 오히려 약 20% 쌈

### 속도: Vercel 함수 시간 예산 안에 넉넉함

- p95 2.6초. 서비스 호출 제한 시간 10초(대체 모델까지 20초)의 1/4 수준
- `gpt-5-mini`(p95 6.2~6.7초)는 제한 시간에 가까워 타임아웃 → 대체 모델 전환이 잦을 위험

### 운영 위험: 현재 권장 세대

- Google 문서 기준 현재 권장 Flash 모델 (Stable)
- 2.5 세대처럼 신규 접근이 막히는 중인 모델은 피함 (실제로 2.5-flash-lite 404)

### 감수하는 것

- **2027-01-01 가격 인상 예정** (현재 단가는 2026-12-31까지 할인가) → 그 전에 재평가
- **Gemini 무료 티어는 입력이 제품 개선에 쓰일 수 있음** → 지금은 전부 가상 데이터라 문제없음. 실제 고객 데이터를 다루면 유료 티어로
- **무료 티어 분당 호출 제한** → 429는 대체 모델(OpenAI)로 넘어가도록 설계

## 9. 왜 대체 모델이 gpt-5.4-mini인가

- **다른 제공사**여야 함
  - 대체 모델의 목적은 기본 모델 쪽 장애(429·5xx·키 문제·모델 종료)에서 서비스를 살리는 것
  - 같은 Google 모델(예: 3.5-flash-lite)이면 Google 쪽 장애·키 문제에 같이 멈춤
- OpenAI 후보 중 최종 프롬프트 기준 **잘못된 답변 0, 정확도 120**은 `gpt-5.4-mini`뿐
  - `gpt-6-luna`도 잘못된 답변 0이지만 정확도 117, 과잉 거절 9 → 대체 상황에서 거절이 늘어남
- 1단계 운영 모델이라 배포 환경에서 이미 검증됨
- 비용은 더 비싸지만 대체 호출은 드물어서 전체 비용 영향이 작음
- 실제로 확인: 기본 모델을 404가 나는 `gemini-2.5-flash-lite`로 두고 호출 → `gpt-5.4-mini`가 2.2초 만에 응답, 사용량 기록에 `fallbackFrom` 남음

## 10. 고르지 않은 모델

| 모델 | 이유 |
|---|---|
| gemini-3.5-flash-lite | 최종 지표는 같고 비용 절반·가장 빠름. 다만 기준 프롬프트에서 q41 3/3 실패 → 프롬프트 변화에 민감. **트래픽이 커지면 1순위 전환 후보** |
| gpt-5-mini | 기준 1위였지만 2·3차에서 q40 잘못된 답변. p95 6초대로 느림 |
| gpt-6-luna | 가장 쌈($0.10). 잘못된 답변 0이지만 과잉 거절 9/96, q27을 3회 모두 거절 |
| gpt-5.4-nano | 3차에서도 q41 1회 재발 |
| gpt-5-nano · gpt-4.1-nano | 기준 평가에서 잘못된 답변 발생, 흔들린 문항 2개 |
| gpt-4.1-mini | 잘못된 답변 7/30으로 최하위. 비추론 모델은 근거 판단에 약함 |
| gemini-2.5-flash | 잘못된 답변 3/30, 비용은 3.8-flash보다 높음, 종료 예정 세대 |

- `gpt-5-nano` · `gpt-4.1` 계열 · `gemini-2.5-flash`는 기준 프롬프트(`da2331be`)로만 평가함. 최종 프롬프트로 다시 재면 순위가 바뀔 수 있음

## 11. 한계와 다음 재평가 시점

- **평가셋이 작음**: 42문항 × 3회. 모델 간 1~2건 차이는 우연일 수 있음. 여기서는 "0건을 세 프롬프트 내내 유지했는가"처럼 반복된 패턴으로 판단
- **평가셋에 맞춘 프롬프트일 수 있음**: 3차 규칙은 q40·q41을 보고 만든 것 → 평가셋 밖 질문(홀드아웃)으로 확인 필요 ([백로그](backlog.md))

- **지연은 한 곳에서 측정**: 한국 가정용 회선 기준. Vercel 리전에서는 다를 수 있음 → 운영 탭의 실제 p95로 확인

  - 2027-01-01 Gemini 3.8 가격 인상 전
  - 판단 프롬프트 변경 시 (비교표의 프롬프트 버전이 달라지면 전부 다시)
