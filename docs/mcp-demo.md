# MCP 시연: Claude Code가 헬프데스크 도구로 일하기

- 일시: 2026-09-28, Claude Code(헤드리스 `claude -p`) + 로컬 stdio MCP 서버 → 공개 데모 API
- 허용한 도구: 읽기 도구 7개. **`reply_to_ticket`은 막음** → 고객에게 실제로 나가는 일 없음
- 결과: 도구 8번 호출, 10턴, 34초
- 연결 방법·설계: [mcp.md](mcp.md)

## 요청

> 너는 가상 OTT 서비스 시네웨이브 고객센터 팀장을 돕는 어시스턴트야. cinewave-helpdesk 도구만 써서 아래 세 가지를 해 줘.
> 1) 오늘 운영 현황을 3줄로 요약하고, 답하지 못한 질문이 몰린 문서 중 먼저 보강할 곳을 골라 줘.
> 2) 문의함에서 가장 오래 기다린 상담원 대기 문의의 맥락을 확인하고, 고객에게 보낼 답장 초안을 다듬어 줘. 실제로 보내지는 말고 초안만.
> 3) 고객이 "아이폰에서 결제했는데 환불은 어디서 해요?"라고 물으면 뭐라고 답할지, 근거 문서와 함께.

## Claude가 호출한 도구 (순서대로)

| # | 도구 | 입력 | 왜 |
|---|---|---|---|
| 1 | `get_ops_report` | - | 운영 현황·보강 후보 |
| 2 | `list_tickets` | status: escalated | 대기 문의 찾기 |
| 3 | `ask_policy` | "아이폰에서 결제했는데 환불은 어디서 해요?" | 3번 질문 (1~3을 병렬로) |
| 4 | `get_ticket` | 가장 오래 기다린 티켓 | 넘김 사유·AI 판단·초안 |
| 5 | `get_policy_doc` | refund | 초안이 정책과 맞는지 원문 대조 |
| 6 | `list_policy_docs` | - | 보강 후보 문서 확인 |
| 7 | `get_policy_doc` | content-schedule / 공개 일정 안내 원칙 | 섹션만 |
| 8 | `get_policy_doc` | coupon-event | 보강 후보 비교 |

- 1~3을 한 번에 호출하고, 결과를 본 뒤 필요한 문서만 **섹션 단위**로 더 읽음 (전체 문서를 다 읽지 않음)

## 답

도구 조회를 다 마쳤어요. 요청하신 세 가지를 정리했습니다.

## 1) 오늘 운영 현황
- **비용·안정성:** 최근 호출 9건, 비용 $0.0096로 하루 예산 $1의 1% 미만이에요. 대체 모델 전환과 실패는 0건입니다.
- **품질(평가셋):** 틀린 답 0/30, 상태 판정 정확도 120/126(95%), 답할 수 있는데 거절한 경우 6/96(6%)예요.
- **문의함:** 7일간 2건이 들어와 1건은 자동 응답, 1건은 상담원 대기입니다. 대기 1건이 **558분째 기다리고 있어 SLA 30분을 넘겼어요.**

**먼저 보강할 문서: `coupon-event`(이용권·쿠폰·이벤트)**
- 답하지 못한 질문은 이 문서와 `content-schedule`에 1건씩이라 건수로는 우열이 없어요.
- `content-schedule`에는 "공지되지 않은 일정은 추측해서 안내하지 않음"이라는 원칙이 이미 있어서, "ㅇㅇ콘텐츠 언제 들어오나요?"에 답하지 못한 건 의도된 결과예요.
- 반면 "학생 할인 있나요?"는 문서에 할인 대상이 아예 없어서 답하지 못했어요. 학생 할인이 있는지 없는지 한 줄만 추가해도 해결됩니다.

## 2) 가장 오래 기다린 상담원 대기 문의
- **고객 원문:** "어제 결제한 거 환불해 주세요. 아무것도 안 봤어요."
- **상담원에게 넘어간 이유:** 환불을 실제로 처리해 달라는 개인 요청이라서예요. 비슷한 과거 처리 사례는 없어요.
- **AI 초안의 문제:** 고객 말만 믿고 "전액 환불이 가능합니다"라고 단정했어요. 시청 이력과 결제 수단은 아직 확인하지 않았습니다.

**다듬은 초안 (발송하지 않음):**
> 안녕하세요, 시네웨이브입니다. 오래 기다리시게 해 죄송합니다.
> 결제 후 7일 이내이고, 결제 이후 콘텐츠를 1분 이상 재생한 기록(예고편 제외)이 없으면 전액 환불해 드립니다. 고객님 계정의 시청 이력을 확인한 뒤 처리 결과를 안내드리겠습니다.
> 아이폰·안드로이드 앱에서 결제하셨다면 저희가 직접 환불해 드릴 수 없어요. 이 경우 해당 앱마켓 고객센터로 환불을 요청해 주세요.
> 환불이 완료되면 이용권이 바로 종료되고, 다운로드한 콘텐츠도 재생할 수 없게 됩니다.

근거는 `refund` 문서의 '기본 원칙', '인앱결제 환불', '환불 후 처리' 섹션이에요. 보내기 전에 상담원이 시청 이력과 결제 수단을 확인해야 합니다.

## 3) "아이폰에서 결제했는데 환불은 어디서 해요?"
> 아이폰 앱에서 결제하셨다면 앱마켓 인앱결제라서 앱마켓 환불 정책을 따릅니다. 시네웨이브 고객센터에서는 직접 환불해 드릴 수 없으니, 앱마켓 고객센터로 환불을 요청해 주세요.

- **근거:** `refund` 문서 > 인앱결제 환불 ("앱마켓 인앱결제는 앱마켓 환불 정책을 따름 / 상담원이 직접 환불 처리할 수 없음")
- **판정:** 확정 답변이고 확신도는 높음이에요.

## 이 시연에서 보인 것

- **답장 초안의 약점을 Claude가 잡음**: 자동 응대가 "개인 처리 요청"으로 넘긴 문의의 AI 초안이 "전액 환불이 가능합니다"로 **단정** — 시청 이력·결제 수단을 확인하기 전인데도. Claude가 원문(`refund`)과 대조해 "확인 후 안내"로 고치고, 인앱결제 예외를 추가
  - 조치 요청은 사람이 처리하려고 넘기는 것이라 초안이 결과를 약속하면 안 됨 → 개선 과제로 [백로그](backlog.md)
- **근거 없는 추측을 하지 않음**: 보강 후보를 고를 때 "`content-schedule`은 추측 금지 원칙대로 답하지 않은 것 → 의도된 동작"으로 구분
- **안전장치가 MCP에서도 그대로**: 되돌릴 수 없는 `reply_to_ticket`은 이 시연에서 허용하지 않았고, 도구 호출은 모두 API의 호출 제한·사용량 기록을 거침
