## 1. 배경

> 입사 3주 차 상담원이 "어제 결제했는데 드라마 한 편 봤어요. 환불돼요?"라는 문의를 받음. 위키엔 환불 문서가 두 개, 옆자리 선배는 "7일 안이면 돼요". 빠진 조건은 **시청 이력이 없어야** 전액 환불. 고객은 재문의하고 "상담원마다 말이 다르다"고 함

- 가상 OTT 서비스 시네웨이브의 고객센터. 상담원이 채팅·전화 문의를 받으며 정책 문서를 수시로 확인
- 상담 인력 이동이 잦음 → 숙련자의 지식이 사람과 함께 빠져나감

## 2. 문제 정의

| 문제 | 현상 | 영향 |
|---|---|---|
| 정답이 사람 기억에 있음 | 문서는 여러 벌, 준비 중·확정 정책이 섞여 있음 | 상담원마다 다른 답 → 재문의, 불만 |
| 반복 문의가 상담원 시간을 씀 | "프리미엄 몇 대까지 돼요?"처럼 문서에 답이 있는 문의도 사람이 처리 | 환불·도용처럼 사람이 봐야 할 문의가 뒤로 밀림 |
| 어떤 문서가 비었는지 모름 | 답하지 못한 질문이 기록되지 않음 | 문서 보강 우선순위를 정할 근거가 없음 |

## 3. 목표와 비목표

### 목표

- 상담원이 **근거와 함께** 정책 답변을 바로 확인
- 확실한 정책 문의는 **사람 없이 자동 응답**, 나머지는 **맥락과 함께** 상담원에게 전달
- 답하지 못한 질문을 모아 **보강할 문서**를 운영자에게 보여 줌

### 비목표 (1차)

- 결제 취소·계정 조치 같은 실제 처리 연동 → 개인 처리 요청은 상담원에게 넘기는 것까지
- 상담원 로그인·배정·권한 관리 → 공개 데모라 누구나 상담원
- 이메일·전화 채널 → 웹 문의 창으로 흐름을 끝까지 만든 뒤

## 4. 사용자

| 사용자 | 상황 | 필요한 것 |
|---|---|---|
| **신입 상담원** | 정책을 다 외우지 못함. 고객을 기다리게 하며 문서를 뒤짐 | 근거가 붙은 답, 고객에게 바로 보낼 문장 |
| **숙련 상담원** | 반복 문의와 신입 질문에 시간을 씀 | 반복 문의 자동 처리, 넘어온 문의의 맥락 |
| **고객** | 간단한 정책을 물어도 상담원 대기 | 확실한 답은 즉시, 아니면 "접수됐다"는 확인 |
| **CS 운영자** | 문서 품질과 상담 품질을 관리 | 미답변 질문, 자동 처리율, 비용·장애 현황 |

## 5. 핵심 원칙

- **틀린 답보다 모르는 답**: 목표는 정답률이 아니라 잘못된 답변 0
- **사람 확인 없이 나가는 답은 확실한 것만**: 자동 응답 기준은 코파일럿보다 한 단계 더 보수적으로
- **검증 가능한 규칙은 코드로**: 프롬프트에만 맡기지 않고 코드가 한 번 더 확인 (인용 없는 답 거절, 근거 밖 숫자 경고 등)
