# 기능정의서

- 기능 ID 체계: `CP` 상담원 코파일럿 · `RP` 고객 답장 · `DC` 정책 문서 · `SP` 자동 응대 · `IB` 문의함 · `NT` 알림 · `OP` 운영 · `SY` 공통·시스템
- 우선순위: P0 출시 필수 · P1 1차 포함 · P2 후속
- 판단 기준·제한값의 상세 값은 [정책정의서](05-policy.md), 화면 배치는 [화면설계서](04-screen-spec.md)

## 1. 상담원 코파일럿

| ID | 기능 | 처리 규칙 | 예외·오류 | 우선순위 | 화면 |
|---|---|---|---|---|---|
| CP-01 | 질문 입력 | 최대 300자. Enter 전송, Shift+Enter 줄바꿈. 한글 조합 중 Enter는 전송 안 함 | 빈 질문 전송 불가. 300자 초과 시 안내. UTF-8이 아닌 입력 거절 | P0 | SC-01 |
| CP-02 | 예시 질문 | 세 가지 답변 상태가 모두 나오는 예시 제공, 칩의 점 색으로 결과 상태 예고 | - | P1 | SC-01 |
| CP-03 | 정책 검색 | 질문을 임베딩해 정책 문서 조각 중 유사도 상위 5개 선택. 하한 0.15 아래는 제외 | 검색 결과 0건 → 모델 호출 없이 '근거 없음' | P0 | - |
| CP-04 | 답변 생성 | 검색된 조각만 근거로 답변. 구조화 출력(상태·답변·인용·근거 판단·요청 유형) | 모델 실패 → 대체 모델로 1회 전환. 둘 다 실패 → 오류 안내 | P0 | SC-01 |
| CP-05 | 상태 교정 | ① 인용 조각이 없으면 '근거 없음'으로 ② 준비 중 문서를 근거로 확정 답을 내면 '준비 중 정책'으로 | - | P0 | - |
| CP-06 | 확신도 | 검색 점수와 모델 근거 판단 중 **약한 쪽**을 따름 (높음·보통·낮음). 확정 답변에만 표시 | 낮음 → "인용 원문을 직접 확인" 경고 | P0 | SC-01 |
| CP-07 | 근거 표시 | 인용 문서 제목·섹션·원문 발췌를 기본 펼침으로 표시, 원문 보기 링크 | - | P0 | SC-01 |
| CP-08 | 검색 추적 | 검색된 조각과 유사도, 실제 근거로 쓴 조각을 구분 표시 | - | P2 | SC-01 |
| CP-09 | 미답변 기록 | '근거 없음'·확신도 낮음 질문을 가장 가까운 문서와 함께 기록 | - | P1 | SC-05 |
| CP-10 | 답변 캐시 | 같은 질문(띄어쓰기·끝 문장부호 차이 무시)은 24시간 동안 저장된 답 재사용. 캐시 적중은 호출 상한에 포함 안 함 | - | P1 | - |
| CP-11 | 링크로 바로 질문 | `?q=질문`으로 바로 실행, `&reply=1`이면 답장 초안까지 | - | P2 | SC-01 |

## 2. 고객 답장 초안

| ID | 기능 | 처리 규칙 | 예외·오류 | 우선순위 | 화면 |
|---|---|---|---|---|---|
| RP-01 | 답장 생성 | 버튼을 누를 때만 생성. 입력은 서버에 저장된 답변(`answerId`)과 인용 근거만 — 클라이언트가 보낸 임의 텍스트는 모델에 넣지 않음 | 없는 `answerId` → 오류 | P0 | SC-01 |
| RP-02 | 상태별 작성 | 확정: 결론 먼저 / 준비 중: "확정되면 공지로 안내"만 / 근거 없음: 보류 답장 | - | P0 | SC-01 |
| RP-03 | 고정 인사말 | 첫 줄 "안녕하세요. 시네웨이브입니다." — 모델이 다른 인사를 쓰면 코드가 교체 | - | P1 | SC-01 |
| RP-04 | 근거 밖 숫자 경고 | 답장의 숫자 중 확인된 답변·근거에 없는 것을 찾아 경고 (번호 목록 머리는 제외) | 경고가 있어도 복사·발송은 가능 (상담원 판단) | P0 | SC-01 |
| RP-05 | 편집·복사 | 초안은 편집 가능한 입력창, 복사 버튼 | - | P0 | SC-01 |
| RP-06 | 초안 재사용 | 한 번 만든 초안은 저장해 같은 답변에 재사용 | - | P1 | - |

## 4. 자동 응대 (고객 문의)

| ID | 기능 | 처리 규칙 | 예외·오류 | 우선순위 | 화면 |
|---|---|---|---|---|---|
| SP-01 | 문의 접수 | 문의를 티켓으로 저장. 저장·모델 호출 **전에** 이메일·전화·카드·주민번호 가림 | 가림 여부를 접수 기록에 남김 | P0 | SC-02 |
| SP-02 | 요청 유형 분류 | 정책 질문(question)과 조치 요청(action: 환불해 주세요, 해지해 주세요 등) 구분 | - | P0 | - |
| SP-03 | 자동 발송 판단 | 자동 발송 기준 5가지를 **모두** 통과해야 자동 응답. 하나라도 걸리면 넘김 + 사유 기록 ([정책 1](05-policy.md#1-자동-발송-기준)) | 모델 실패 → 넘김(사유: 처리 실패), 접수는 유지 | P0 | - |
| SP-04 | 자동 응답 | 답장 초안을 고객에게 발송, 상태 '자동 응답' | - | P0 | SC-02 |
| SP-05 | 넘김 | 상태 '상담원 대기', 고객에게 접수 안내 표시, 맥락 수집(SP-06), 알림(NT-01) | - | P0 | SC-02 |
| SP-06 | 맥락 수집 | 고객 원문, 넘김 사유, AI 판단·확신도·근거, 가까운 문서와 점수, 비슷한 과거 처리(질문 유사도 0.5 이상 상위 3건), 답장 초안 | 비슷한 처리가 없으면 "아직 없음" 표시 | P0 | SC-03 |
| SP-07 | 대화 표시 | 이 브라우저에서 보낸 문의만 대화로 표시. 상담원 대기 중이면 10초마다 갱신해 상담원 답장 반영 | 서버 연결 실패 → 안내 문구 | P1 | SC-02 |
| SP-08 | 예시 문의 | 예시마다 예상 경로 표시 (자동 응답 / 사유 → 상담원) | - | P1 | SC-02 |

## 8. 공통·시스템

| ID | 기능 | 처리 규칙 | 우선순위 |
|---|---|---|---|
| SY-01 | 호출 제한 | IP별 분당 20회, IP별 하루 모델 호출 30회, 전체 하루 300회 ([정책 5](05-policy.md#5-호출-제한과-비용)) | P0 |
| SY-02 | 목업 모드 | 호출 상한 초과·서버 연결 실패 시 평가 때 저장한 실제 응답으로 동작, 화면에 이유 표시 | P1 |
| SY-03 | 대체 모델 | 기본 모델이 일시 오류(시간 초과·5xx·429)나 제공사 문제(401·403·404)로 실패하면 다른 제공사 모델로 한 번 더. 요청 자체 오류(400·422)는 전환하지 않음(코드·스키마 버그를 가리지 않게) | P1 |
| SY-04 | 헬스체크 | `/api/health`: 검색 조각 수, 마지막 동기화, 현재 모델 | P1 |
| SY-05 | 일시정지 방지 | 하루 한 번 `/api/keepalive`로 DB 조회 (Supabase 무료 7일 비활성 일시정지 방지), `CRON_SECRET` 필요 | P1 |
| SY-06 | MCP 서버 | 도구 8개(정책 질문, 답장 초안, 문서 목록·원문, 문의함 목록·상세, 답장·종결, 운영 현황). 원격 `/api/mcp`, 로컬 stdio. 같은 API를 거쳐 호출 제한 그대로 적용 | P2 |

## 9. API

| 메서드 · 경로 | 기능 | 관련 |
|---|---|---|
| `POST /api/ask` | 정책 질문 → 답변 + `answerId` | CP-03~07 |
| `POST /api/reply` | `answerId` → 고객 답장 초안 | RP-01~04 |
| `GET /api/docs` | 정책 문서 목록·원문 | DC-01~03 |
| `POST /api/tickets` | 고객 문의 접수 → 자동 응답 또는 넘김 | SP-01~06 |
| `GET /api/tickets` · `GET /api/ticket` | 문의함 목록 · 상세 | IB-01, 02 |
| `POST /api/ticket-reply` | 상담원 답장·종결 | IB-03 |
| `POST /api/ticket-review` | 사후 검수 | IB-04 |
| `GET /api/tickets-stats` · `GET /api/tickets-overdue` | 자동 응대 지표 · SLA 초과 목록(n8n) | OP-03, NT-02 |
| `POST /api/ticket-event` | n8n 알림 결과 기록 | NT-01 |
| `GET /api/ops` | 운영 현황 | OP-01~05 |
| `GET /api/health` · `GET /api/keepalive` | 헬스체크 · 일시정지 방지 | SY-04, 05 |
| `POST /api/mcp` | MCP (Streamable HTTP, 무상태) | SY-06 |
