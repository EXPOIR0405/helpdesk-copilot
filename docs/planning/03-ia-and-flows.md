# IA · 서비스 플로우

## 1. IA (정보 구조)

```mermaid
flowchart TB
  ROOT["CineWave 상담 코파일럿"]
  ROOT --> A["상담 #/<br/>SC-01"]
  ROOT --> B["고객 문의 #/support<br/>SC-02"]
  ROOT --> C["문의함 #/inbox<br/>SC-03"]
  ROOT --> D["정책 문서 #/docs<br/>SC-04"]
  ROOT --> E["운영 #/ops<br/>SC-05"]

  A --> A1["질문 입력 · 예시 질문"]
  A --> A2["답변 카드<br/>상태 · 확신도 · 근거"]
  A --> A3["고객 답장 초안"]
  A --> A4["검색 추적"]

  B --> B1["대화 (내 문의)"]
  B --> B2["문의 입력 · 예시 문의"]

  C --> C1["목록<br/>상담원 대기 · 자동 응답 · 처리 완료"]
  C --> C2["상세 #/inbox/&lt;id&gt;<br/>AI 판단 · 가까운 문서 · 비슷한 과거 처리 · 답장 · 기록"]

  D --> D1["문서 목록"]
  D --> D2["원문 #/docs/&lt;id&gt;?s=&lt;섹션&gt;"]

  E --> E1["요약 카드"]
  E --> E2["미답변·저확신 질문"]
  E --> E3["자동 응대"]
  E --> E4["비용·안정성"]
  E --> E5["품질 지표"]
```

| 메뉴 | 주 사용자 | 목적 |
|---|---|---|
| 상담 | 상담원 | 정책 질문에 근거와 함께 답을 확인하고 고객 답장 작성 |
| 고객 문의 | 고객 (데모에선 방문자) | 문의를 보내고 자동 응답 또는 상담원 답장을 받음 |
| 문의함 | 상담원 | 넘어온 문의를 맥락과 함께 처리 |
| 정책 문서 | 상담원 | 근거 원문 확인 |
| 운영 | CS 운영자 | 문서 보강, 자동 응대·비용·품질 관리 |

- 메뉴 순서는 상담원의 하루 흐름 순: 질문 확인(상담) → 고객 입장 확인(고객 문의) → 처리(문의함) → 원문(정책 문서) → 관리(운영)
- 데모에서는 고객 문의와 상담원 화면을 한 사이트에 둠 → 방문자가 양쪽 입장을 모두 체험

## 2. 서비스 플로우

### F-01 상담원: 정책 질문 → 고객 답장

```mermaid
flowchart TD
  S([고객 문의를 받음]) --> Q[상담 화면에 질문 붙여 넣기]
  Q --> R{검색 결과?}
  R -- 없음 --> U[근거 없음<br/>담당자 확인 안내]
  R -- 있음 --> M[답변 생성 + 상태 교정]
  M --> ST{상태}
  ST -- 확정 --> C{확신도}
  C -- 낮음 --> W[인용 원문 직접 확인 경고]
  C -- 높음·보통 --> OK[답변 + 근거 확인]
  W --> OK
  ST -- 준비 중 --> P[요금·일정 약속 금지 안내]
  OK --> RP[고객 답장 만들기]
  P --> RP
  U --> RP2[보류 답장 만들기]
  RP --> N{근거 밖 숫자?}
  RP2 --> N
  N -- 있음 --> NW[경고 확인 후 수정]
  N -- 없음 --> SEND[복사해서 고객에게 발송]
  NW --> SEND
  U -.-> LOG[(미답변 기록<br/>→ 운영 화면)]
  W -.-> LOG
```

### F-02 고객: 문의 → 자동 응답 또는 넘김

```mermaid
flowchart TD
  S([고객 문의 입력]) --> PII[개인정보 가림]
  PII --> T[티켓 생성]
  T --> J[코파일럿 판단 + 요청 유형 + 답장 초안]
  J --> G1{조치 요청?}
  G1 -- 예 --> ESC
  G1 -- 아니오 --> G2{확정 답변?}
  G2 -- 아니오 --> ESC
  G2 -- 예 --> G3{확신도 높음?}
  G3 -- 아니오 --> ESC
  G3 -- 예 --> G4{근거 밖 숫자 없음?}
  G4 -- 아니오 --> ESC
  G4 -- 예 --> AUTO[자동 응답 발송<br/>상태: 자동 응답]
  ESC[넘김 + 사유 기록<br/>상태: 상담원 대기] --> CTX[맥락 수집]
  CTX --> MSG[고객에게 접수 안내]
  CTX --> NOTI[n8n → Slack 알림]
  CTX --> IB[(문의함)]
```

- 모델 호출 실패 시에도 접수는 유지하고 사유 '처리 실패'로 넘김

### F-03 상담원: 넘어온 문의 처리

```mermaid
flowchart TD
  N([Slack 알림 또는 문의함 배지]) --> L[문의함 · 상담원 대기 탭]
  L --> D[티켓 상세]
  D --> V[AI 판단 · 넘김 사유 확인]
  V --> H[가까운 문서 · 비슷한 과거 처리 참고]
  H --> E[답장 초안 수정]
  E --> SEND[고객에게 보내고 종결]
  SEND --> R[상태: 처리 완료<br/>고객 대화에 상담원 답장 표시]
  R -.-> SIM[(다음 비슷한 문의의<br/>과거 처리 후보)]
```

### F-04 운영자: 문서 보강과 SLA

```mermaid
flowchart LR
  subgraph 매일
    O[운영 화면] --> U[미답변 묶음<br/>건수 많은 문서부터]
    U --> FIX[문서 보강]
    FIX --> SYNC[동기화<br/>바뀐 문서만]
  end
  subgraph 10분마다
    CR[n8n] --> OV{대기 30분 초과?}
    OV -- 예 --> SL[Slack SLA 알림<br/>60분마다 재알림]
  end
  subgraph 자동 응답 검수
    A[자동 응답 탭] --> RV{맞음 · 틀림}
    RV -- 틀림 --> EV[(평가셋 후보)]
  end
```

## 3. 티켓 상태 전이

```mermaid
stateDiagram-v2
  [*] --> 접수
  접수 --> 자동응답: 자동 발송 기준 통과
  접수 --> 상담원대기: 기준 하나라도 걸림 · 처리 실패
  상담원대기 --> 처리완료: 상담원 답장·종결
  자동응답 --> 자동응답: 사후 검수(맞음·틀림)
  처리완료 --> [*]
```

| 상태 | 코드 | 고객에게 보이는 것 | 상담원에게 보이는 것 |
|---|---|---|---|
| 자동 응답 | `auto_replied` | AI 자동 응답 | 자동 응답 탭, 사후 검수 |
| 상담원 대기 | `escalated` | "문의가 접수되었습니다" | 대기 탭, 사유·대기 시간 |
| 처리 완료 | `resolved` | 상담원 답장 | 처리 완료 탭 |
